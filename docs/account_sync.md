# Account Sync（アカウント同期）

Google ログイン済み端末間で Project と直前正常計算結果を同期する契約の正本です（#185）。端末ローカル優先（Local-first）、可逆圧縮による大容量対応、競合時の明示選択、および削除 Undo と期限付き削除確定を規定します。アカウント削除と世代分離は [アカウント削除](account_deletion.md) を参照してください。

## 設計方針とアクセス制御境界

- **ドメイン独立性**：Project や計算結果の内容自体はクラウド固有のデータ型やサーバー時刻に依存させません。
- **本人照合と改ざん防止**：リモート側のアクセス制御では、クライアントが申告した識別子・メールアドレス・表示名ではなく、**認証済みトークンの Google 本人識別子と保存先の所有者一致** のみを信頼します。未知の保存先や削除済み記録の物理消去は拒否します。
- **Local-first の保証**：自動保存は通信前に必ず端末内へ確定します。サイズ超過・通信失敗・利用枠制限が発生しても、未同期の送信待ちを保持したまま利用者に影響を通知し、端末内 Project を退避削除したり Legacy へ切り替えたりしません。

<a id="large-project-payloads"></a>
## 大容量 Project の可逆圧縮と上限

リモートの 1 件あたり上限（1 MiB）に対し、保存形式の互換性や端末側の記録内容を損なわず大容量 Project に対応します。

- **自動圧縮と格納上限**：**256 KiB** 以上で可逆圧縮を適用し（圧縮後の方が小さい場合のみ採用）、格納サイズ上限を **1,000,000 バイト**（1 MiB 制限内のメタデータ余白確保）とします。
- **完全可逆性**：Project 項目・チェックポイント・計算結果・来歴・数値精度を一切欠落させません。過去の非圧縮データも引き続き読み取れます。
- **安全上限と失敗時保護**：不正データの無制限展開を防ぐため展開後サイズ上限を **16 MiB** とし、破損データやサイズ上限超過は書込前に安全側で失敗させます（レコード分割や無制限容量は提供せず、ローカルデータと送信待ちを保護します）。

## 永続同期契約・匿名データ取込・`Latest` の扱い

- **同期状態と計画データの分離**：Project 本体・下書き・計算結果とは独立して同期状態（排他バージョン・送信待ち・競合・削除猶予）を管理し、確認済み保存より古い遅延通知を拒否します。確認応答の喪失時も同じ操作単位で冪等に再試行できます。
- **原子的グループ更新とオフライン閲覧**：関連する更新グループ全体を一括で成功または失敗させます。送信中のローカル編集は未同期として維持し、クライアントの楽観的キャッシュだけでサーバー確定済みとみなしません。同期済みデータは一覧表示・閲覧をオフラインで行えます（ただし未キャッシュのアプリ本体配信を代替する完全オフライン機能ではありません）。
- **匿名データの取込**：ログイン時に端末内の適格な匿名レコードを 1 回取り込み、元のレコードは匿名側で「取込済み（匿名・他アカウントから不可視）」として中断再開用に保持します。名前付き Project は即座にアカウント統合へ入り、匿名 `Latest` は直ちにローカルで閲覧・編集可能としつつ、既存クラウド側 `Latest` の上書きを防ぐため初回統合完了を待ってアップロードします（クラウド側の既存 `Latest` と衝突した場合は、名前付き保存または破棄をダイアログで確認し、選択前の終了・再読み込みでは保持します）。
- **端末ごとの `Latest`**：1 ブラウザ／プロファイルにつき 1 端末として扱い、アカウント `Latest` は最後に編集した端末に属します（閲覧だけで所有権は移りません）。別 Project を開くか同一端末の `Latest` を置き換えると旧 `Latest` を削除済み記録として確定します（他端末の `Latest` と全明示保存チェックポイントは保持）。競合コピーは独立した新しい名前付き保存 Project となり、第 2 の `Latest` にはなりません。

## 競合解決と復旧

- 他端末・サーバー側で先に更新されていた場合、端末上の最初の編集はローカルに保持したまま以後の編集をロックし、**「Local を残す / Remote を採用 / 両方保存（Both）」の明示選択** を求めます（黙って後勝ち上書きやフィールド自動マージは行いません）。
- 「両方保存（Both）」ではサーバー側の Project ID を維持し、ローカル側の変更を新しい Project ID へ複製して一体で確定します。同じ競合の再試行で余分な複製を増殖させません。
- 選択された側の計算結果は現在の入力と整合するかを再検証し、古い（stale）場合は除外して別状態の Project へ誤添付しません。読込キャンセル時は現在の作業ベースラインを差し替えません。

<a id="削除と-undo-pending_delete"></a>
## 削除と Undo

- 削除操作時は即座に削除猶予状態と猶予期限を記録して一覧から隠し、約 **10 秒間** の Undo スナックバーを表示します。この状態と期限は他端末へも同期され、Undo 実行時は有効状態へ戻します。
- **期限経過による確定**：猶予期限を過ぎると、クライアントやサーバータイマーが稼働していなくてもサーバー側ルールにより復活不可となり **実質削除確定** となります。これは永続的な削除記録であり、物理消去やゴミ箱機能ではありません。オフライン削除時はアップロードまで元の期限を保持し、古いローカル分岐を別 Project として残すことはできても削除済み Project を復活させることはできません。
