# SEA先行評価・差分再利用の検証（Issue #526）

2026-11-26の合成DEM試験で、CP編集後の画素評価と要求数が減ることを確認した。初回のChromium観測JSヒープは増加したため、iOS実機での資源負荷・応答性の受入は未完了とする。

## 測定条件

基準は `227ecfcba2b5acf590e01108ed04ba7cf1ad6d3a`、変更後のソース識別と全測定値は [results.json](results.json) に記録する。Linux、Node v24.18.1、Playwright 1.62.1、CPU 8–11で測定した。並行する差分検証はCPU 0–3へ分離した。

同じ 137.890 NM・2 Leg・8 CPの経路と合成DEMで、初回、CPを経度0.00002度移動、同CP削除を順に各1回実行した。変更後は中間キャッシュを維持する。端末プロファイルはDesktop Chrome、iPad (gen 7)、iPhone 13。iOS実機ではなくLinux上のブラウザエンジン試験である。

各タイルは65,536画素の固定標高を返す。通信遅延、PNG復号、Pythonの領域生成、Project保存、UI描画は測定に含めない。アプリ全体の編集時間ではなく、地形評価・キャッシュの比較である。本体が保存済みの未変更区間を省く処理も、この測定では省かず再集約する。

全18操作で評価完了を確認した。比較のため取得の60秒上限を付けずに完走させた。実アプリでは上限を維持する。時間差には評価範囲と画素列挙方式の変更の両方を含む。単回の観測であり、統計的な速度保証や実通信・実機への一般化は行わない。

## 要求数・評価量

3構成で次の件数は一致した。要求数は合成タイル提供関数の呼出し回数で、実HTTP通信数ではない。画素数は領域間の重複を含む。

| 操作 | タイル要求 前→後 | 評価画素 前→後 |
| --- | ---: | ---: |
| 初回 | 870 → 865 | 52,075,802 → 44,808,279 |
| CP移動 | 870 → 14 | 52,075,797 → 321,040 |
| CP削除 | 870 → 14 | 51,325,761 → 319,106 |

CP編集後は147領域の中間結果を再利用し、境界部分を再評価した。差分の最高値・被覆結果と全評価の一致は `terrain-unit.spec.ts`、左右扇形とCP前方地形の除外は `test_sea.py` でも検証した。

## メモリと永続キャッシュ

| Chromiumの観測JSヒープ | 変更前 (MiB) | 変更後 (MiB) |
| --- | ---: | ---: |
| 初回 | 101.4 | 151.6 |
| CP移動 | 108.8 | 70.3 |
| CP削除 | 103.9 | 68.8 |

タイル要求時と操作終了時に観測した最大値であり、真のピークではない。GCの実行時期にも左右される。WebKitではこのJSヒープ指標を取得できず、実機iOSでのメモリ上限や応答性は未検証である。

初期案の16枚保持では初回1,060要求となった。32枚で865要求、64枚で857要求だったため、要求数と保持量の両方を考慮して32枚にした。中間評価は8 MiB・2,048領域で上限を設け、今回の保持量は最大575,395 bytes（約0.55 MiB）だった。生タイルを永続保存しない。

専用IndexedDBはProject/Account Syncから分離し、保存拒否・消失時は有限のセッションキャッシュと再評価で継続する。Linux WebKitで初期CacheStorage案の再読込保持が確認できず、IndexedDB案の4ブラウザ構成テストが通ったことを採用根拠とする。一般的なSafariの不具合とは断定しない。
