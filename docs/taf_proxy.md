# 目的地 TAF 用 Serverless Proxy

Local（Static Web）環境で目的地 TAF のみ（`ICAO` コード単位）を取得し、NAV LOG 計算本体・Project 保存・認証・MSM 取得から分離するための境界仕様です（#145）。Legacy 環境の TAF 取得は移行期間中そのまま維持します。

## 境界と失敗時の振る舞い

- Local 環境では、FORECAST 計算時に目的空港の **4 文字 ICAO コードのみ** を専用 Proxy へ送信します（FTD モード、起動復元、保存、読込では取得しません）。
- Proxy へは ICAO のみを送り、Cookie、認証情報、Project 内容、出発時刻、計算結果は送信しません。ブラウザ側の取得制限時間は **7 秒** です。
- 取得した有効レコード（または取得不可の理由）は計算コア共通の判定（TEMPO / PROB 除外の卓越風選択・到着予定時刻での有効性判定）で扱い、表示側で独自の TAF 解釈を重複実装しません。
- **失敗時の隔離**：設定未構成、7 秒タイムアウト、通信・HTTP・利用枠超過・形式不正はいずれも目的地 TAF の参考欄が「取得不可」（UI 表示「`目的地風: 取得できませんでした`」）になるだけで、アプリケーションエラーや計算ブロッカーにはなりません。自動リトライ、上流への直接フォールバック、期限切れキャッシュの成功扱いは行いません。
- **計算・保存の不変性**：TAF は最終情報行の参考表示専用であり、到着区間は常に CALM 計算となるため、WCA・MH・GS・ETE・燃料は変化しません。TAF 取得が失敗しても計算自体は通常どおり完了し、Project と新しい計算結果（TAF 取得不可を含む）を端末内保存します（保存自体の失敗時は [Local Persistence](local_persistence.md) の保護規則を適用）。

## 不正利用対策と無料枠境界

- **最小許可入力**：単一空港の 4 文字英数字 ICAO 照会（読み取り専用）のみを受理し、余分・重複パラメータや別パス・別メソッドは拒否します。
- **固定上流と厳格な検証**：上流は AviationWeather.gov の TAF API に固定し、リクエストヘッダや Cookie は転送せず、リダイレクトにも追従しません。上流応答タイムアウト **5 秒**、本文上限 **64 KiB**、対象空港一致を検証します。
- **アクセス元制御**：許可済みオリジン一覧と完全一致するオリジンからの要求のみ応答し、空設定・ワイルドカード・本番での `localhost` は禁止します。
- **同時数・キャッシュ・レート制限**：
  - 実行単位あたりの上流同時取得を **4 件** に制限し、超過時は待ち行列を作らず拒否します。
  - 検証後の有効なエッジキャッシュ応答（正常 TAF **5 分**、空応答 **1 分**、エラーは保存しない）を優先して上流負荷とレート消費を抑えます（期限切れフォールバックなし）。
  - 実際の上流取得を開始する場合のみ、クライアント IP ごと **20 件/分**、全体 **60 件/分**、同一空港 **1 件/分** を上限とします（制限機構に異常がある場合は安全側に拒否）。
- **限界とゼロコスト方針**：オリジンヘッダは認証ではなく非ブラウザからは偽装可能であり、エッジのレート制限や同時数制御も全世界厳密上限ではありません。本 Proxy は **Cloudflare Workers Free 枠のまま（有料プランへ自動移行しない）** で運用し、日次上限到達時は翌日リセットまで TAF のみ利用不可となる設計を受け入れます。上流から過負荷応答を受けた場合もリトライで増幅させません。
